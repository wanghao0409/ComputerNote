# SPARK

## 一、定义与理解

Spark 是一个<u>基于内存的</u>**、**<u>分布式的</u>、用于<u>大规模数据处理</u> 的统一分析引擎。

- **基于内存**：核心优势，计算中间结果可放内存，避免像 MapReduce 那样频繁读写磁盘，速度极快（官方称比 Hadoop MapReduce 快 100 倍）。
- **分布式**：数据和处理能力分布在成百上千台机器上。
- **统一分析引擎**：**这是 Spark 最强大的地方！** 一套技术栈解决批处理、交互式查询、实时流处理、机器学习、图计算等多种任务。

### 核心组件

| 模块                       | 作用                            |
| :----------------------- | :---------------------------- |
| **Spark Core**           | 底层核心，提供 RDD API、任务调度、内存管理     |
| **Spark SQL**            | 处理结构化数据，DataFrame/Dataset API |
| **Structured Streaming** | 实时流处理                         |
| **MLlib**                | 机器学习库                         |
| **GraphX**               | 图计算                           |
|                          |                               |
|                          |                               |

## 二、程序运行架构

1.

| 组件                  | 作用                                 |
| :------------------ | :--------------------------------- |
| **Driver Program**  | 用户编写的主程序，定义 RDD 变换和动作，启动 Spark 应用  |
| **Cluster Manager** | 资源调度器，如 Standalone、YARN、Kubernetes |
| **Executor**        | 运行在工作节点上的进程，执行具体 Task，并存储数据缓存      |
| **Task**            | 最小执行单元，每个任务处理一个数据分区                |

### Spark 应用执行流程

1. **代码编写**：用户编写 Spark 应用程序，包含 Transformations 和 Actions
2. **DAG 构建**：调用 Action 时，Spark 根据 RDD 依赖关系构建 DAG
3. **DAG 调度**：DAGScheduler 将 DAG 划分为多个 Stage（基于宽依赖）
4. **任务调度**：TaskScheduler 将每个 Stage 的任务集提交给 Cluster Manager
5. **任务执行**：Executor 在 Worker 节点上执行具体任务
6. **结果返回**：最终结果返回给 Driver 或写入外部存储


```bash
spark-submit \
  [集群与运行模式参数] \
  [应用程序信息参数] \
  [资源配置参数] \
  [依赖管理参数] \
  你的应用程序主文件 [程序启动参数]
```

## 三、RDD 弹性分布式数据集

### 1. RDD 概念

**Resilient Distributed Datasets**——一个**不可变的**、**分区的**、**可并行计算**的数据集合。只读。

- **弹性（容错性）**：通过**血缘关系**实现——如果一个 RDD 的分区数据丢了，可根据其来源（"父" RDD）和转换操作重新计算。
- **分布式**：数据被分区后分散在集群不同节点上。数据来源即 HDFS，block 对应 RDD 的 partition。

### 2. RDD 算子

**算子就是对 RDD/DataFrame 进行操作的方法**，分两大类：

| 类别                     | 特点       | 说明                                               |
| :--------------------- | :------- | :----------------------------------------------- |
| **Transformation（转换）** | **懒加载**  | 只定义计算逻辑，不立即执行，返回新 RDD/DataFrame                  |
| **Action（动作）**         | **立即执行** | 触发所有累积的 Transformation 实际运行，返回结果给 Driver 或写入外部存储 |

> **面试金句**：一个 Spark 应用由一个或多个 Job 组成，每个 Job 由一个 Action 触发。

#### ① Transformation 转换算子

惰性执行：只记录转换关系，不计算。

**Value 数据类型转换：**

| 算子 | 描述 | 特点 |
| :--- | :--- | :--- |
| **`map(func)`** | 对每个元素应用 func，一对一转换 | 最基础，使用最频繁 |
| **`filter(func)`** | 过滤掉使 func 返回 false 的元素 | 数据清洗必备 |
| **`flatMap(func)`** | 对每个元素应用 func 后压平结果 | 一对多，常用于分词 |

**Key-Value 数据转换（最重要！）：**

| 算子 | 描述 | Shuffle? | 特点 |
| :--- | :--- | :--- | :--- |
| **`groupByKey([numPartitions])`** | 按 Key 分组 | **有** | 性能较差，优先用 reduceByKey |
| **`reduceByKey(func, [numPartitions])`** | 按 Key 聚合 | **有** | **Map 端预聚合，性能优** |
| **`aggregateByKey(zeroValue)(seqOp, combOp)`** | 更通用的按 Key 聚合 | **有** | 可改变返回值类型 |
| **`sortByKey([ascending], [numPartitions])`** | 按 Key 排序 | **有** | 全局排序 |
| **`join(otherRdd, [numPartitions])`** | 内连接 | **有** | 类似 SQL 的 JOIN |

#### ② Action 动作算子

通过 RDD 计算得到一个值或一组值，**真正触发计算**。

| 算子 | 描述 |
| :--- | :--- |
| **`count`** | 返回 RDD 元素个数 |
| **`collect`** | 拉取所有数据到 Driver（慎用，可能 OOM） |
| **`take(n)`** | 拉取前 n 条数据（生产环境多用） |
| **`reduce(func)`** | 按 func 聚合所有元素 |
| **`countByKey()`** | 统计每个 Key 出现次数，返回 Map |

### 3. RDD 之间的依赖关系

| 类型 | 关系 | 是否 Shuffle | 典型算子 |
| :--- | :--- | :--- | :--- |
| **窄依赖** | 父 RDD 每个分区最多被子 RDD **一个**分区使用（一对一） | **否** | `map`, `filter`, `union` |
| **宽依赖** | 父 RDD 一个分区会被子 RDD **多个**分区使用（多对一/多对多） | **是** | `groupByKey`, `reduceByKey`, `join` |

> **关键**：宽依赖是划分 Stage 的依据，也是 Shuffle 的来源。

### 4. 常用算子对比（面试高频）

1. **`map` vs `mapPartitions`？**
   - `map`：逐元素处理，函数调用频繁。
   - `mapPartitions`：以分区为单位处理，可在分区开始时创建资源（如数据库连接），处理完后关闭，避免频繁创建销毁开销。**但可能引起 OOM**，因为要加载整个分区数据到内存。

2. **`reduceByKey` vs `groupByKey`？**
   - **永远优先使用 `reduceByKey`**！它有 Map 端 Combiner，能大幅减少 Shuffle 数据量。`groupByKey` 会把所有数据不经处理地通过网络传输，性能极差。

3. **`coalesce` vs `repartition`？**
   - `coalesce`：用于**减少**分区，默认**不进行 Shuffle**。如从 1000 个分区合并到 100 个，效率高。
   - `repartition`：用于**增加或减少**分区，**一定会触发 Shuffle**。如需数据打散更均匀，或从 4 个分区增加到 100 个。

4. **如何选择 `collect` 和 `take`？**
   - `collect`：拉取**所有数据**到 Driver。数据量大时会导致 Driver OOM，**仅用于测试或结果集极小的场景**。
   - `take(n)`：只拉取前 n 条数据，安全可靠，生产环境多用 `take`。

## 四、DataFrame / Dataset

> **Spark 2.x/3.x 的现代核心**，构建在 RDD 之上的高级抽象。

### 1. 概念

- **DataFrame**：可以看作**一张分布式表格**，有行和列（带 Schema 信息），类似 Pandas DataFrame 或数据库表。
- **Dataset**：DataFrame 的强类型版本（Scala/Java），编译期类型检查；Python 中只有 DataFrame。

### 2. RDD vs DataFrame

| 对比项 | RDD | DataFrame |
| :--- | :--- | :--- |
| 抽象层级 | 底层核心，灵活但原始 | 高级抽象，构建在 RDD 之上 |
| Schema | 无 | 有（带结构信息） |
| 优化 | 无优化器，用户自负优化 | **Catalyst 优化器** + Tungsten 执行引擎 |
| API 易用性 | 函数式，偏底层 | SQL 风格 + DSL，更易用 |
| 性能 | 一般 | 更高效（有优化） |

> 一句话：**RDD 是基础，DataFrame 是高级抽象，通过优化器提供更高效、更易用的 API。**

### 3. SparkSession

Spark 2.0+ 的统一入口，取代了旧的 SparkContext + SQLContext + HiveContext：

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder \
    .appName("my_app") \
    .master("local[*]") \
    .getOrCreate()
```

### 4. 常用操作

```python
df = spark.read.json("data.json")    # 读取
df.printSchema()                     # 查看 Schema
df.select("name", "age").show()      # 查询列
df.filter(df.age > 20).show()        # 过滤
df.groupBy("dept").count().show()    # 聚合
df.createOrReplaceTempView("people") # 注册为临时视图
spark.sql("SELECT * FROM people WHERE age > 20").show()  # SQL 查询
```

## 五、执行计划 DAG & Stage

> 这是理解 Spark 作业执行的核心。**根据宽依赖划分 Stage，从而划分 Task。**

### 1. 核心概念

| 概念 | 含义 |
| :--- | :--- |
| **Job** | 一个 Action 触发一个 Job |
| **Stage** | Job 内部按宽依赖划分的执行阶段，Stage 内部是窄依赖，可流水线执行 |
| **Task** | Stage 内按分区划分的最小执行单元，一个分区一个 Task |

### 2. 执行流程

1. 代码遇到 **Action** → 触发一个 **Job**
2. DAGScheduler 根据 **宽依赖** 将 Job 划分为多个 **Stage**（Stage 内为窄依赖，可 pipeline 流水线执行）
3. 每个 Stage 内按分区生成多个 **Task**，组成 TaskSet
4. TaskScheduler 将 TaskSet 提交给 Executor 执行

```
代码 → Action → Job → (按宽依赖切分) → Stage1 → Stage2 → ...
                                          ↓
                                    按分区生成 Task
```

> **关键**：窄依赖可在同一 Stage 内流水线执行；遇到宽依赖就切出一个新的 Stage，因为需要 Shuffle。

## 六、性能优化

### 1. 分区（Partitioning）
- RDD/DataFrame 被划分为多个分区，每个分区由一个 Task 处理。
- 合理设置分区数可提高并行度。

### 2. 持久化（Persistence / Caching）
- 使用 `persist()` 或 `cache()` 将 RDD 存入内存，避免重复计算。

```python
rdd.cache()  # 第一次计算后缓存到内存
```

### 3. 广播变量（Broadcast Variables）
- 将只读大变量广播到所有节点，避免每个 Task 重复发送。

### 4. 累加器（Accumulators）
- 用于计数或求和的共享变量，**只能被 Driver 读取**。

### 5. 数据倾斜（经典难题）
- **现象**：绝大多数 Task 很快完成，个别 Task 极慢，导致整个作业卡住。
- **解决方案**：
  - **预处理**：过滤掉导致倾斜的异常 Key（如 null 值）。
  - **加盐**：将倾斜的 Key 加随机前缀，打散分布；处理完再去掉前缀合并结果。
  - **提高 Shuffle 并行度**：通过 `spark.sql.shuffle.partitions` 参数增加分区数。

## 七、运行模式

| 模式                  | 适用场景              | 特点                                                    |
| :------------------ | :---------------- | :---------------------------------------------------- |
| **Local 本地模式**      | 开发、测试和调试          | 简单易用，无需集群环境                                           |
| **Standalone 独立模式** | 中小规模集群，无需外部集群管理器  | 手动启动 Master/Worker；支持 HA（通过 ZooKeeper 实现 Master 故障恢复） |
| **YARN 模式**         | 已部署 Hadoop 的大数据集群 | YARN 负责资源管理和任务调度                                      |
| **Mesos**           | 需与其他框架共享资源的集群     | 支持细粒度和粗粒度资源调度                                         |
| **Kubernetes 模式**   | 基于容器的云原生环境        | 支持动态资源分配和容器化部署                                        |
